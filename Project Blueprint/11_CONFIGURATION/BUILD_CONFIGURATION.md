# Build Configuration

How Mooziac is built, packaged, and run.

## Build command

```bash
swift build              # debug build
swift build -c release   # release build
```

- Build products land in `.build/` (gitignored).
- Binary path via `swift build -c release --show-bin-path` → `$BIN_DIR/Mooziac`.

## `build_app.sh` pipeline (5 steps)

1. **Kill** existing `Mooziac`/`YTMMenuBar` processes.
2. **Release build** via `swift build -c release`.
3. **Assemble bundle** at `~/Applications/Mooziac.app`:
   - `Contents/MacOS/Mooziac` (binary, `chmod +x`)
   - `Contents/Resources/` ← copied **only** from repo `Resources/` (AppIcon.icns, MOOZIAC_transparent.png, launch_transparent.png, MOOZIAC.png, MenuBarIcon.png, MenuBarIcon@2x.png, trackpad.html, macbook_panel.jpg)
   - `Contents/Info.plist` (hand-written heredoc)
4. **Ad-hoc sign**: `codesign --force --deep --sign - --identifier "com.local.Mooziac"`.
5. **Launch**: `open "$TARGET_APP"`.

## Info.plist contents (hand-authored)

| Key | Value |
| :--- | :--- |
| CFBundleExecutable | `Mooziac` |
| CFBundleIdentifier | `com.local.Mooziac` |
| CFBundleName / DisplayName | `Mooziac` |
| CFBundleIconFile | `AppIcon.icns` |
| CFBundlePackageType | `APPL` |
| CFBundleShortVersionString | `1.0.0` |
| LSUIElement | `true` (menu-bar only) |
| NSHighResolutionCapable | `true` |
| CFBundleURLTypes | scheme `mooziac` |

## Package.swift

- Tools version 5.9; platform macOS 13+.
- Single executable target `Mooziac`, path `Sources/Mooziac`, `dependencies: []`.
- Subfolders compile recursively — no per-folder manifest changes needed.

## Notes / caveats

- No Info.plist in the source repo — generated by script (customize in `build_app.sh`).
- No entitlements, no signing identity (ad-hoc only) → not notarized; Gatekeeper may warn on first run.
- Bundle id `com.local.Mooziac` is fixed in three places (script sign step, plist).
- Adding a new runtime asset requires editing `build_app.sh`'s copy block.
- No CI configuration in repo.
